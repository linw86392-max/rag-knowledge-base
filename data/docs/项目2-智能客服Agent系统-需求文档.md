# 智能客服 Agent 系统需求文档

> 版本：v1.0 | 作者：林旺 | 日期：2026-08

---

## 一、项目背景

企业内部员工日常咨询大量重复性问题（工单查询、审批进度、制度咨询等），人工客服响应慢、成本高。本系统基于大模型构建智能客服 Agent，通过工具调用（Function Calling）打通业务系统，实现多轮对话中自主查询数据、解答问题，降低人工咨询量。

## 二、项目目标

1. 支持多轮对话与上下文记忆，能持续追问不跑偏
2. 具备工具调用能力，Agent 自主查询工单、审批等业务数据
3. 工具调用失败有重试与兜底，系统稳定不宕机
4. 回答可控、可溯源，控制 Token 成本

## 三、技术选型

| 模块 | 选型 | 说明 |
|------|------|------|
| 开发语言 | Python 3.10+ | 主语言 |
| Agent 框架 | LangGraph 0.2+ | 状态驱动的 Agent 工作流 |
| LLM | DeepSeek API / 通义千问 API | 支持 Function Calling |
| 本地模型 | Ollama + Qwen（可选） | 离线演示、私有化 |
| 向量记忆 | Chroma | 长期记忆存储 |
| 后端框架 | FastAPI | 接口与流式输出 |
| 前端 | React + Ant Design | 对话界面 |
| 容器化 | Docker | 部署 |

## 四、功能需求

### 4.1 对话模块

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 多轮对话 | 支持连续追问，上下文连贯 | P0 |
| 意图识别 | 区分"查知识库"与"调工具"两类意图 | P0 |
| 流式输出 | SSE 打字机效果 | P0 |
| 会话管理 | 新建/历史会话列表/继续会话 | P1 |
| 人工介入 | 复杂问题转人工（HITL） | P2 |

### 4.2 工具调用模块

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 工具定义 | 用 JSON Schema 定义工具参数 | P0 |
| Function Calling | Agent 自主决策调用工具、传参 | P0 |
| 模拟业务工具 | 工单查询、审批状态查询、制度查询（Mock API） | P0 |
| 参数校验 | 参数缺失时 Agent 主动反问用户 | P1 |
| 失败重试 | 工具调用失败自动重试（最多2次） | P1 |
| 超时兜底 | 超时返回友好提示，不中断对话 | P1 |

### 4.3 记忆模块

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 短期记忆 | 最近 N 轮对话保留 | P0 |
| 上下文压缩 | 超阈值自动摘要压缩，控 Token 成本 | P1 |
| 长期记忆 | 用户偏好/历史沉淀到向量库 | P2 |

### 4.4 可观测与评估

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 链路日志 | 记录每轮意图、工具调用、耗时 | P1 |
| 对话回放 | 查看单次对话的完整调用链路 | P2 |
| 反馈标注 | 点赞/点踩收集 Bad Case | P1 |

## 五、核心业务流程

### 5.1 Agent 主循环（ReAct）

```
用户提问 → 读取会话记忆
   → LLM 决策：直接回答 or 调用工具
   ├─ 调用工具 → 参数校验 → 执行工具 → 结果回填 LLM → 生成回答
   ├─ 工具失败 → 重试(2次) → 仍失败则兜底提示
   → 追加回答到记忆 → SSE 流式返回
```

### 5.2 LangGraph 状态图设计

```
                    ┌────────────┐
                    │   开始      │
                    └─────┬──────┘
                          ▼
                    ┌────────────┐
                    │  意图识别    │
                    └─────┬──────┘
              ┌───────────┴───────────┐
              ▼                       ▼
     ┌────────────────┐     ┌────────────────┐
     │ 知识库回答(RAG)  │     │ 工具调用(Execute)│
     └───────┬────────┘     └───────┬────────┘
              └───────────┬─────────┘
                          ▼
                    ┌────────────┐
                    │  生成回答    │
                    └─────┬──────┘
                          ▼
                    ┌────────────┐
                    │  是否需要    │
                    │ 更多工具?    │ ──否──► 结束
                    └─────┬──────┘
                          │是（循环回执行）
```

## 六、接口设计

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/chat | 对话接口（SSE 流式） |
| GET | /api/sessions | 会话列表 |

## 七、模拟业务工具（Mock）

| 工具名 | 说明 | 参数 |
|--------|------|------|
| query_work_order | 查询工单状态 | order_id |
| query_approval | 查询审批进度 | approval_no |
| query_leave_balance | 查询年假余额 | employee_id |

> 先用本地 Mock 数据，后续可替换为真实业务 API。

## 八、页面设计

1. **对话页**：消息列表 + 输入框 + 会话列表侧栏，支持流式渲染、工具调用卡片展示（"正在查询工单 #10086..."）
2. **反馈机制**：每条回答下方点赞/点踩

## 九、部署方案

```
本地开发（Mock 工具） → Docker 容器化
   → 云服务器部署 / Ollama 本地模型离线演示
```

## 十、验收标准

1. 连续 5 轮追问上下文不跑偏
2. 工具调用成功率 ≥ 90%，失败有重试与兜底
3. 回答 30 个测试问题，正确率 ≥ 70%
4. 端到端响应延迟 < 5 秒（含工具调用）
5. 能清晰演示"规划-调用-反思"的完整链路
