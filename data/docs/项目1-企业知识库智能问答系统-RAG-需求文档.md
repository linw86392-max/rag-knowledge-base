# 企业知识库智能问答系统（RAG）需求文档

> 版本：v1.0 | 作者：林旺 | 日期：2026-08

---

## 一、项目背景

企业日常存在大量非结构化文档（制度文件、设备手册、审批规范等），员工查询需要逐篇翻找，效率低且口径不一。本系统通过 RAG（检索增强生成）技术，将企业文档转化为可检索的知识库，员工通过自然语言提问即可快速获取带来源引用的准确回答。

## 二、项目目标

1. 支持批量导入 PDF/Word/Markdown 文档，自动完成解析、分块、向量化入库
2. 支持自然语言问答，回答附带来源文档与页码溯源，可一键跳转原文
3. 实现多知识库隔离与权限管控
4. 提供 Token 用量与调用成本统计，辅助成本控制

## 三、技术选型

| 模块 | 选型 | 说明 |
|------|------|------|
| 开发语言 | Python 3.10+ | 主语言 |
| 大模型框架 | LangChain 0.3+ | 文档加载、分块、提示词、检索链 |
| LLM | 通义千问 API / DeepSeek API | OpenAI 兼容协议 |
| Embedding | text-embedding-v2（阿里云） | 中文效果好、免部署 |
| 向量数据库 | Chroma（本地） | 开发简单、面试易演示 |
| 后端框架 | FastAPI | 高性能、原生支持 SSE |
| 前端 | Streamlit（演示）→ React（正式） | 先快后全 |
| 容器化 | Docker | 一键部署 |

## 四、功能需求

### 4.1 文档管理模块

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 文档上传 | 支持 PDF / Word / Markdown 批量上传，单文件≤20MB | P0 |
| 文档解析 | PDF 抽取文字，Word 解析，Markdown 直接读取 | P0 |
| 文档分块 | 语义分块（500字 + 100字重叠），保留标题层级 | P0 |
| 向量化入库 | Embedding 后写入 Chroma，记录来源与页码 | P0 |
| 知识库管理 | 创建/删除知识库，按知识库隔离文档 | P1 |
| 文档删除 | 支持删除文档并同步清理向量 | P1 |

### 4.2 问答模块

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 自然语言问答 | 用户输入问题，返回带引用的回答 | P0 |
| 引用溯源 | 回答末尾列出来源文档、标题、页码，可跳转原文 | P0 |
| 流式输出 | SSE 打字机效果，提升交互体验 | P0 |
| 多轮对话 | 短期会话记忆，支持追问（上下文补全） | P1 |
| 无答案拒答 | 检索相关性低于阈值时明确告知"知识库中未找到"，不硬答 | P1 |
| 答案反馈 | 点赞/点踩，收集 Bad Case 用于优化 | P2 |

### 4.3 权限与统计

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 多知识库隔离 | 不同部门知识库互不可见 | P1 |
| 用户权限 | 管理员/普通用户角色 | P1 |
| 调用统计 | 记录每日问答数、Token 用量、缓存命中率 | P2 |
| 效果评估 | 简单评测集 + 人工标注回答质量 | P2 |

## 五、核心业务流程

### 5.1 文档入库流程（离线）

```
上传文档 → 格式校验 → 文本解析 → 文本清洗
   → 语义分块（500字+100重叠） → 元数据标注（来源/页码）
   → Embedding 向量化 → 写入 Chroma → 更新文档状态
```

### 5.2 问答流程（在线）

```
用户提问 → 问题改写（补全上下文）
   → Embedding 向量化问题 → Chroma Top-K 检索
   → 重排序（Rerank） → 相关性阈值判断
   → 拼接 Prompt + 检索上下文 → LLM 生成回答
   → 追加引用来源 → SSE 流式返回前端
```

## 六、接口设计

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/kb/upload | 上传文档建立索引 |
| DELETE | /api/kb/document/{id} | 删除文档及向量 |
| GET | /api/kb/list | 知识库/文档列表 |
| POST | /api/qa/ask | 问答接口（SSE 流式） |
| POST | /api/qa/feedback | 答案反馈 |
| GET | /api/stats/usage | Token 用量统计 |

## 七、页面设计

1. **文档管理页**：上传入口、文档列表（状态：解析中/已入库/失败）、知识库切换
2. **问答页**：左侧知识库选择，中间对话区（流式渲染），回答下方显示引用来源卡片，支持点击跳转
3. **统计页**（P2）：今日问答数、Token 消耗折线图

## 八、部署方案

```
本地开发 → Docker 容器化（Python 服务 + Chroma 数据卷）
   → 部署到云服务器 / Streamlit Cloud（演示）
```

## 九、验收标准

1. 上传 10 份 PDF 文档后，问答准确率 ≥ 70%（人工评测 50 个问题）
2. 回答必须带来源引用，引用可跳转原文
3. 流式输出首 token 延迟 < 2 秒
4. 与"知识库无关"的问题能正确拒答，不胡编
5. Docker 一条命令可启动
